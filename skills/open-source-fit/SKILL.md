# 开源项目适配调研

目标：找到能解决用户当前问题的开源方案，说明能直接使用什么、需要改造什么、哪些部分只值得学习，以及下一步如何验证。

## 1. 先建立项目画像

已有项目先读项目规则、README 和当前摘要，再按需查看相关业务规则、模块及接口；不默认加载全部历史。新项目从用户已提供的需求建立画像。

记录当前任务、必须满足的业务流程、已有技术栈和实现、不能改变的规则、预算、运行资源、目标设备与网络条件。把“必须”“可后置”“未知”分开。

信息不足时先完成不依赖它的搜索，只询问会改变筛选结论的问题。不要再次询问文档中已确认的业务决定；历史配置不能直接当成当前可用资源。

## 2. 分层寻找候选

按缺口搜索：成品系统、开发底座、专项组件、可借鉴设计。使用中文业务词和英文同义词组合，不限于项目的营销名称。

需要选择网站和组织搜索词时，读 [搜索入口](references/search-sources.md)。按当前需求选入口，不为每次任务机械遍历全部网站。

先用目录、精选榜单和代码托管搜索发现候选，再回到维护者的官方仓库、文档、版本发布与许可证核实。Star、榜单名次和项目介绍只作发现线索。

使用当前环境可用的搜索、浏览或仓库工具；本技能不依赖指定插件或 CLI。无法联网或某站读取受限时，标明覆盖缺口，基于已有材料给出暂定结论，不能伪称已完成在线核验。

## 3. 核对真正可用的范围

对进入重点比较的候选，核对：

- **身份与版本**：官方仓库、分支/标签，必要时记录 commit；避免同名项目、镜像和历史版本混淆。
- **需求证据**：重点功能对应官方文档、源码入口或演示。README 宣传、源码存在、隔离运行、真实业务验收是不同证据层级。
- **免费范围**：所需功能是否在公开代码中；安装所需 SQL、插件、身份登录、权限、审计或集成是否收费/缺失。公开文档和在线演示不证明免费代码可完整运行。
- **使用条件**：核对所评估版本及组件/模型/权重/数据集各自的许可、声明保留和适用限制；许可缺失或条款不清楚时标为待核实，不能直接认定允许商业复用。复杂条款留给相应专业核验。
- **实际代价**：语言与数据库兼容性、服务数量、算力/内存/存储、运维、外部 API、迁移、培训和持续维护。没有依据时描述工作项与不确定性，不编造费用或工期。
- **维护与环境**：发布、修复、问题处理、安装文档和依赖状态；目标地区的资源可达性、目标手机与浏览器、现有人员能力。不要仅凭最后一次 commit 的日期否定稳定项目。

时效性事实以本轮官方资料为准。证据直接链接到支持结论的页面或具体源码；写明未读到、未运行、未核验的部分。

## 4. 将功能映射回业务流程

对关键需求逐项标记“直接满足 / 需要适配 / 仅可借鉴 / 不满足 / 待核实”，说明理由和证据，不用一个总分掩盖关键缺口。

重点检查容易被界面掩盖的差异：公司或租户隔离、记录和附件权限、授权到期与撤销、负责人移交后的访问、离线与补传、业务幂等、审批与付款状态、不同模块的实体和编码是否贯通。按项目实际涉及的部分检查。

多个模块共用后台不等于数据或业务流程已打通；PWA 不等于离线关键流程可靠；多公司不自动要求微服务。不同语言的模块通常只能复用设计，不能声称直接复制即可运行。

## 5. 给出采用路线和最小验证

按证据将候选落到合适路线：保留现项目并接入组件、参考设计做局部改造、采用开源底座、使用成品系统，或暂不采用。根据当前阶段、投入与收益推荐，保留用户明确选定的方向。

先给能够解决当前缺口的最小方案，再说明长期扩展。整体替换必须解释新增收益、迁移工作及现有功能如何承接，不因开源项目功能多而扩大用户范围。

给推荐方案设计一条有通过/失败标准的最小业务验证：需要什么环境、使用哪些合成数据、验证哪条端到端链路、预期结果、失败后的替代路线。身份、弱网、附件权限或跨模块联动等关键假设不能只看截图。

用户要求“先讨论”时，交付方案及验证计划后停止实施。若已授权试用，可在授权范围内做隔离验证；调研本身不授权安装执行上游程序、申请付费服务、Star/发消息、接触真实业务数据、迁移或部署。需要决定时先完成可审阅的具体方案，再提必要的问题。

## 6. 交付可复核的结论

需要形成报告时，使用 [调研报告模板](references/research-template.md)，按任务大小裁剪。至少包括项目画像、候选与需求映射、推荐路线、代价与关键缺口、证据、未验事项和下一步。

搜索受限与淘汰理由简短记录；“本轮未找到”不写成“市场上不存在”。默认中文，用户另有要求则遵从；用户可见日期与时间使用 Asia/Shanghai，并标注北京时间。

理解此流程如何从真实项目抽象而来时，读 [历史案例](references/historical-example.md)。该案例用于解释判断方法，不是今天的产品推荐或固定技术选型。
